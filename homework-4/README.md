# Homework 4 — Agentic Bug-Fix Pipeline

**Course:** GenAI and Agentic AI for Software Engineering
**Author / student:** ash (`ash@firelink.media`)

A chain of six Claude Code sub-agents that **research → verify → plan → fix → security-review
→ test** a deliberately-buggy sample app, run end-to-end from **one command**. The whole
thing is a file-based data flow: each agent reads the previous artifact and writes the next.

---

## What's in here

Two things are built at once, and they are kept separate on purpose:

- **The tooling** (the graded deliverable): the agents in [`agents/`](agents/) and the skills
  in [`skills/`](skills/) that *do* the work.
- **The subject**: a small **expense-tracker REST API** in [`src/`](src/) that ships with
  intentional defects for the tooling to *act on*, so the pipeline produces concrete
  before/after results.

```
CLAUDE.md              Binding project contract (stack, models, seeded bugs — read this first)
run-pipeline.sh        Single-command orchestrator
package.json           express + jest + supertest
src/                   The buggy expense-tracker API
tests/                 Unit tests (generated by the pipeline)
context/bugs/00X/      bug-context.md documenting each seeded defect
agents/                Six *.agent.md definitions
skills/                research-quality-measurement.md, unit-tests-FIRST.md
docs/screenshots/      Evidence of the run
```

## The pipeline

```
Bug Researcher      ─→ research/codebase-research.md
Research Verifier   ─→ research/verified-research.md      (skill: research-quality-measurement)
Bug Planner         ─→ implementation-plan.md
Bug Fixer           ─→ fix-summary.md    (edits src/, runs npm test)
Security Verifier   ─→ security-report.md                 (report only — no code edits)
Unit Test Generator ─→ test-report.md + tests/*.test.js   (skill: unit-tests-FIRST)
```

Agents don't call each other — they communicate through **artifact files**. The Researcher
and Planner are *upstream* (they generate input from scratch); the Verifier, Fixer, Security
Verifier, and Test Generator are the four required agents that *consume and act on* a prior
artifact. Researcher and Verifier are deliberately different agents so the verification is an
**independent** fact-check, which is exactly what Task 1 grades.

## The sample app and its seeded defects

`src/` is an in-memory expense-tracker API (`POST /expenses`, `GET /expenses` with
`category/from/to` filters, `GET /expenses/:id`, `GET /summary`, `DELETE /expenses/:id`).
It ships broken, with each defect documented in `context/bugs/`:

| # | Type | Where | Defect |
|---|------|-------|--------|
| [001](context/bugs/001/bug-context.md) | Logic | `GET /summary` | Ignores the query filter — totals every expense, so the summary disagrees with the filtered list. |
| [002](context/bugs/002/bug-context.md) | Boundary | `filterExpenses()` | Date range uses `<` instead of `<=`, dropping a record dated exactly on `to`. |
| [003](context/bugs/003/bug-context.md) | **Security** | `DELETE /expenses/:id` | API key is **hardcoded in source** and compared with loose, non-constant-time `==`. |

After a pipeline run the same app demonstrates the fixes and passes the generated tests.

## Per-agent model selection (required)

Each `*.agent.md` names its model in frontmatter; `run-pipeline.sh` passes it via `--model`.
The rule: **Opus** where an error is expensive and independent judgment is graded, **Sonnet**
everywhere else. Haiku is intentionally unused — edit/test reliability was preferred over a
wider cost spread.

| Agent | Model | Why this model |
|-------|-------|----------------|
| Bug Researcher | `claude-sonnet-5` | Breadth-first exploration across the source; needs solid code reading, not the deepest reasoning — Sonnet balances quality and cost. |
| Research Verifier | `claude-opus-4-8` | Independently fact-checks every `file:line` and grades research quality; a wrong "pass" here corrupts everything downstream, so it gets the strongest reasoning. |
| Bug Planner | `claude-sonnet-5` | Designs the concrete before/after fix; the plan is later validated by the Fixer's tests, so Sonnet is sufficient. |
| Bug Fixer | `claude-sonnet-5` | Applies an explicit plan and runs tests — mechanical, but chosen over Haiku for reliable multi-file edits. |
| Security Verifier | `claude-opus-4-8` | Security judgment and severity rating on the changed code; the brief explicitly calls for stronger reasoning on security review. |
| Unit Test Generator | `claude-sonnet-5` | FIRST tests must cover the boundary case (bug 002); needs real reasoning to write meaningful, non-trivial tests. |

## Skills (mandatory, and actually used)

- **[`skills/research-quality-measurement.md`](skills/research-quality-measurement.md)** —
  defines what a claim is, the Verified/Discrepant/Unresolvable verdicts, the A/B/C/D quality
  scale, the PASS/FAIL gate, and the required five-section shape of `verified-research.md`.
  Loaded into the **Research Verifier**.
- **[`skills/unit-tests-FIRST.md`](skills/unit-tests-FIRST.md)** — defines **FIRST** (Fast,
  Independent, Repeatable, Self-validating, Timely) with concrete Jest/supertest rules and a
  boundary-testing discipline. Loaded into the **Unit Test Generator**.

`run-pipeline.sh` inlines each skill into its agent's prompt, so the skill is loaded
automatically rather than by hand.

## How AI was used

This assignment *is* an AI-agent system, so AI is used at two levels:

- **As the deliverable** — the six agents are Claude models with per-task model selection;
  they perform the research, verification, fixing, security review, and test generation.
- **In authoring** — Claude Code was used to scaffold the sample app, design the seeded
  defects, write the agents/skills, and build the orchestrator. Every seeded defect was
  verified to reproduce (live `curl` output) before the pipeline was pointed at it, and the
  binding decisions are recorded in [`CLAUDE.md`](CLAUDE.md) so they aren't silently
  re-litigated. See the PR description for the full narrative and screenshots.
